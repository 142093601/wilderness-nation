# AI 设定文本：提示词、约束与样例

> 用途：批量生成**残言、碑文、事件旁白、任务描述**这类"设定文本"，人工挑 20% 用。
> 手工写几十上百条会累死，而这类文本**正是 AI 最划算的用法**：短、有格式、有约束、可批量、人工筛选成本极低。

---

## 一、三条硬约束（违反任何一条，产出就是废的）

1. **不许新增设定**。只能使用 `DESIGN.md` 世界观一节已有的元素：**旧世 / 潮（尸潮）/ 渊（深渊）/ 归返者 / 命名词根（垣·渡·烽·渠·仓）**。AI 爱自创新神、新种族、新魔法——**一律不要**。
2. **不许解释旧世为什么崩溃**。留白是功能。残言只能"露出边角"，不能给答案。
3. **不许写成小说**。不写对话、不写人物、不写连续剧情。**只写一句或几句能被刻在石头上的话。**

## 二、质量判据

| 好的残言 | 坏的残言 |
|---|---|
| 短、断言、像工匠的笔记 | 长、抒情、像小说开头 |
| 露出一个具体的失败细节（"湿木"、"第四堆烽火"） | 抽象地说"我们曾辉煌" |
| 顺带教会一条玩法规则 | 只讲气氛，与玩法无关 |
| 让人想问"然后呢" | 把"然后呢"答完了 |

**最有价值的形态：把游戏机制写进旧世的教训里。** 这样残言同时是**设定**与**软教学**——满足 C 节"身份进既有信息流"的原则，还省掉一个教学关。

## 三、提示词模板

### 残言（残破图纸上的旧世残句）

```
角色：你是旧世的记录者，写下的是残破图纸上仅存的一两句话。
约束：
- 只使用这些元素：旧世 / 潮 / 渊 / 归返者 / 命名词根（垣 渡 烽 渠 仓）
- 不解释旧世为何崩溃；不要新增设定、神、种族、魔法
- 每条 15~40 字，断言式，像工匠或军官留下的实用笔记
- 每条必须顺带指向一条真实的玩法规则（门要窄、粮分三处、烽火三堆即撤、登记名字…）
- 输出格式：`残图·<词根> —— 「<残言>」`
数量：20 条，风格尽量不重复
```

### 碑文（时代碑 / 毕业工程 / 事故碑）

```
角色：你是这个国家的刻碑人。
约束：
- 文体：编年体，第三人称，不用第一人称复数以外的称呼
- 事故碑只记事、不定性、不追责（例：`1512 · 大火 · 烧掉西仓 · 无人伤亡 · 重建用了 3 天`）
- 时代碑要点：这一时代做成了什么 + 谁在场 + 留下什么未完成
- 每条不超过 60 字
```

### 事件旁白（袭击 / 世界事件来临时的一句话气氛文本）

```
角色：你是这个世界的旁白，不出现"系统""玩家""服务器"这类词。
约束：
- 一句话，20~50 字，只写可观察的现象（声音、方向、数量、天色）
- 不预告结果、不报参数（不写"20 只僵尸"）
- 与预警机制呼应：可说方向与"还有多久"，但不承诺具体事件
```

### 任务描述（任务书的 27 个任务）

```
角色：你是这个国家的任务书作者。
约束：
- 每条任务描述 40~80 字：要做什么 + 为什么 + 怎么算完成
- 用国策口吻（"建立公共仓库并存入 1000 单位物资"），不写"收集 64 个铁"
- 尽量写成需要协作的事；单人能做但要慢得多
- 不剧透后续时代的内容
```

## 四、已生成的样例（15 条残言）

> 这批是**实际产出**，不是模板。注意其中有多条顺带教了玩法规则。

| # | 残言 | 顺带指向的玩法 |
|---|---|---|
| 1 | 残图·渡 —— 「西岸的桥在第三年塌了。别再用湿木。」 | 图纸材料与耐久意识 |
| 2 | 残图·垣 —— 「墙要够厚，但门要够窄。我们死在门上，不是死在墙上。」 | 城门是最薄弱环节 |
| 3 | 残图·烽 —— 「烽火点三堆就是撤，不要等第四堆。第四堆没人点得着。」 | 预警信号的语言（C8） |
| 4 | 残图·渠 —— 「水往低处走，人往有水处走。渠修好之前，别往下游建。」 | 选址标准（第十一节） |
| 5 | 残图·仓 —— 「粮食分三处放。一处烧了还能活，一处被占就得走。」 | 公共仓库的分散布置 |
| 6 | 残图·渡 —— 「潮水来的时候，桥是给人跑的，不是给车过的。」 | 袭击时交通的用途 |
| 7 | 残图·垣 —— 「我们把碑立在墙里。塌了也还在。」 | 碑林即留存（9.8③） |
| 8 | 残图·烽 —— 「值夜的人不要一个人。第二个人的用处不是打架，是记得喊。」 | 敲钟集结与望风分工（D8） |
| 9 | 残图·渠 —— 「闸门向西开。东边的土吃不住水。」 | 工程要按地形定 |
| 10 | 残图·仓 —— 「登记本上写名字。东西丢了要有人问，问不出来才会再丢。」 | 功勋墙与约定（E） |
| 11 | 残图·垣 —— 「旧世的墙比我们高，还是没守住。区别不在墙。」 | 防御五层不止屏障（10.1④） |
| 12 | 残图·渊口 —— 「不要往下挖。它在往上长，不是往下。」 | 深渊是同化型威胁 |
| 13 | 残图·渡 —— 「渡口选在河弯内侧。外侧年年塌。」 | 桥址与地形判断 |
| 14 | 残图·烽 —— 「灯塔要成链。孤零零一座，只是给潮水指路。」 | 灯塔链要给预警网络（9.7） |
| 15 | 残图·仓 —— 「冬储要按人头算，不按功劳算。饿死的人不看功劳簿。」 | 公共物资的分配原则（E2） |

> **注意第 11 条**：它一句话就把"城墙不是万能解"这个设计点讲完了（因为 `hordeMobsCanClimbEachOther` 默认开启）。**残言可以是最高效的教学**——玩家在捡到碎片的兴奋里读到了规则，而不用去读教程。

## 五、用法（v0：不需要 API key）

1. 取上面任一模板，填上上下文（例如"本时代是 1515 远行纪"）；
2. **拿进 DSH 会话里生成**（会话本身就是一个 AI，不需要额外配 API）；
3. **人工挑 20%**——这一步不能省：AI 一次给 20 条，好的大概 4~6 条；
4. 落成 `lore/残言.md`，再放进图纸碎片的工具提示、议事厅的成书、或告示牌。

**为什么先人工挑**：AI 的产出里总有几条"看起来对但味道不对"（太抒情、太现代、或偷偷加了新设定）。挑的动作就是质量控制，而它比从头写便宜一个数量级。
