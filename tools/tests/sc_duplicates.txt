# 重复村民的自愈验收（§10.3）
#
# 背景：2026-09-20 那个"区块没加载 → 误判村民不在 → 再刷一个"的 bug，已经在这个世界里
# 留下过 6 个同名文书。修好之后再加一道闸：**同一个 buildingId 只许有一个村民**，
# 多出来的会被清掉（判据是我们自己的持久化标签，不是"附近所有村民"）。
#
# 这个脚本手工造一个"冒牌文书"（同样的标签、另一个 UUID），然后确认它被认出来、被清掉。

# 0) 先记下当前状态。**不要求 healthy=true**：在没有玩家在线的服务端上，
#    绑定的村民可能根本没装进世界（`DEFERRED.md` §J），那时 healthy 会是 false ——
#    这条脚本验的是**重复村民的自愈**，与 §J 无关，所以只要求命令能跑。
cmd: /statecraft buildings
expect: STATECRAFT_BUILDINGS count=\d+

# 1) 造一个带同样标签的冒牌文书（原版 summon + 我们的持久化标签）
cmd: summon minecraft:villager 104.5 152.0 103.5 {NoAI:1b,NeoForgeData:{"statecraft:profession":"scribe","statecraft:building":"intel_station@minecraft:overworld:103,151,103"}}

# 2) 现在应该报出 1 个重复
cmd: /statecraft buildings
expect: duplicates=[1-9]

# 3) 跑一次实体化：顺手清掉重复
cmd: /statecraft materialize
expect: 清掉了

# 4) 恢复干净
cmd: /statecraft buildings
expect: duplicates=0

# 5) 而且**不许把正经的那个也删了**：边界仍在，且绑定的 UUID 没变
#    （不要求 healthy=true —— 那是 §J 的事；字段之间会随功能增加而变，所以用 .* 连接）
cmd: /statecraft buildings
expect: bound=true.*duplicates=0
